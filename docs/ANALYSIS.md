# SSSMS 분석 및 설계 문서

> Smart Self-Study Management System — 야간자율학습실(야자실) 통합 관리 시스템

## 1. 레퍼런스 서비스 분석

| 서비스 | 핵심 UX 패턴 | SSSMS에 적용한 점 |
|---|---|---|
| **모두의출석 (com.yyp.moduchulseok)** | 태블릿 키오스크 출석 → 학부모/관리자 알림, 출결 통계, 관리자 웹 | 키오스크·관리자·학생 3단 구조, 출결 로그/통계 |
| **열품타 (열정을 품은 타이머)** | 큰 숫자 타이머, 일별 공부시간 **잔디(히트맵)**, 그룹 내 랭킹 | 홈 화면 "오늘 공부시간" 히어로 숫자, 120일 히트맵, 주간 랭킹 |
| **듀오링고** | 🔥 **연속 스트릭**, 최고 기록, 주간 달력 체크 | 연속 출석일/최고 연속 기록, 주간 출석 도트 |
| **토스 만보기** | 오늘 달성 진행률 링, 단순한 한 화면 요약 | 일일 목표(기본 3시간) 대비 진행 링 |
| **스터디카페 키오스크 (작심·토즈 등)** | 좌석 배치도에서 색상으로 공석/사용중 구분 → 터치로 선택 | 키오스크·학생앱 좌석 맵 (초록=공석, 회색=사용중, 파랑=내 자리, 노랑=지정석) |
| **얼굴인식 출입 (Suprema, 출입통제 솔루션)** | 카메라 응시 → 1초 내 인식, 실패 시 대체 수단 | 얼굴 인식 + 라이브니스 → 입실/퇴실 자동 판별 |

공통 UX 원칙
- **키오스크**: 큰 터치 타깃(≥64px), 한 화면 한 작업, 자동 리셋(무조작 15초 후 대기화면 복귀), 음성/색으로 결과 피드백.
- **학생 모바일**: 하단 탭바, 첫 화면에 동기부여 지표(시간·스트릭), 카드형 레이아웃.
- **관리자 웹**: 좌측 사이드바 + 테이블/대시보드, PC·모바일 반응형.

## 2. 시스템 구조

```
┌────────────────┐   ┌────────────────┐   ┌──────────────────────┐
│ 학생 모바일웹  │   │ 관리자 웹      │   │ 출석 키오스크(태블릿) │
│ /student       │   │ /admin         │   │ /kiosk               │
│                │   │ 얼굴 등록(카메라)│  │ Human.js (WebGL/WASM) │
└───────┬────────┘   └───────┬────────┘   │ 검출→랜드마크→임베딩  │
        │ REST/JSON (Bearer 토큰)        │ 안티스푸핑+라이브니스  │
        └──────────────┬─────────────────┴──────────┬───────────┘
                       ▼                            │ 임베딩(1024-d)만 전송
              ┌───────────────────┐                  │ (사진 원본 미전송/미저장)
              │ Node.js API 서버  │◀─────────────────┘
              │ server/index.js   │  1:N 코사인 매칭, 단기 티켓 발급
              │ node:sqlite       │  자동 퇴실 스케줄러, 퇴출후보 산정
              └───────────────────┘
```

- 외부 의존성 0개(Node 22.5+ 내장 `node:sqlite`, `node:http`, `node:crypto`).
- 프런트는 빌드 없는 Vanilla JS 정적 페이지. 얼굴 AI는 CDN의 `@vladmandic/human@3.3.6`.

## 3. 얼굴 인식 파이프라인 (사용 모델/기법)

| 단계 | 모델 | 설명 |
|---|---|---|
| 얼굴 검출 | **BlazeFace** (MediaPipe) | 경량 SSD 계열, 모바일 실시간 |
| 랜드마크 | **FaceMesh 468pt + Iris** | 눈 깜빡임/입 벌림/고개 회전(yaw, pitch) 계산 |
| 얼굴 임베딩 | **FaceRes** (ResNet 계열, 1024-d descriptor) | 정렬된 얼굴 → 특징 벡터 |
| 안티스푸핑 | **Anti-Spoof CNN** (Silent-Face 계열 텍스처 분석) | 사진·화면 재촬영의 모아레/반사/질감 판별 → `real` 점수 |
| 라이브니스 | **Liveness CNN** | 실제 사람 여부 확률 → `live` 점수 |

### 3.1 "진짜 사람 얼굴인지" 확인 — 다층 방어 (PAD, ISO/IEC 30107-3 개념)
1. **Passive PAD**: 매 프레임 `real`(안티스푸핑)·`live`(라이브니스) 점수를 누적 평균 → 임계값(기본 0.5) 미만이면 거부. 인쇄 사진·휴대폰 화면 공격 차단.
2. **Active PAD (Challenge–Response)**: 매번 **무작위 순서**로 2가지 동작 요구
   - 눈 깜빡임: 홍채/눈꺼풀 랜드마크 기반 blink 검출
   - 고개 좌·우 회전: yaw 각도가 ±0.25rad 이상 양방향 변화
   - 입 벌리기: 입 벌림 비율 > 30%
   → 녹화 영상 재생 공격(replay) 방지. 제한시간 12초.
3. **동일인 연속성**: 챌린지 시작·종료 시점 임베딩 유사도 ≥ 0.55 + 화면 내 얼굴 1명만 허용 → 중간에 다른 사람/사진 바꿔치기 방지.
4. **서버 검증**: 클라이언트가 보낸 PAD 점수를 서버 임계값으로 재검증, 매칭은 서버에서만 수행.

### 3.2 매칭 알고리즘
- 등록 시 정면 4장 + 좌우 4장 + 위아래 4장 캡처 → L2 정규화 임베딩 12개 저장. '얼굴 추가 등록'으로 안경 벗은 모습 등을 덧붙일 수 있음(최대 36개).
- 인식 시 챌린지 동안 수집한 임베딩 평균 → 정규화 → 모든 학생 임베딩과 **코사인 유사도**.
- 학생별 최대값(top-1)이 임계값(기본 0.6) 이상 **AND** 2위와의 차이(margin) ≥ 0.05 → 인식 성공(오인식 억제).
- 성공 시 60초 유효 1회용 **티켓** 발급 → 입실(좌석 선택)/퇴실 요청에 사용.

## 4. 주요 비즈니스 규칙
- **입/퇴실 자동 판별**: 열린 세션이 없으면 입실, 있으면 퇴실.
- **지정석 학생**: 입실 시 지정 좌석 자동 배정. **자율석 학생**: 키오스크 좌석맵에서 공석 선택.
- **자동 퇴실**: 운영 종료시각(기본 23:00) 이후 미퇴실 세션은 종료시각으로 강제 퇴실 처리(`auto=1`).
- **지정석 퇴출 후보**: 지정석 보유 학생 중 최근 N일(평일, 기본 3일) 연속 미출석 → 관리자 대시보드 후보 목록.
- **블랙리스트**: 입실 차단, 사유 표시.
- **공부시간**: 세션(check_in~check_out) 합계. 스트릭 = 하루 1분 이상 출석일 연속 수.

## 5. 개인정보 보호
- 얼굴 원본 이미지 저장/전송 없음, 임베딩 벡터만 저장(관리자가 언제든 삭제 가능).
- 비밀번호 scrypt 해시, 토큰 기반 세션.
- 운영 시 HTTPS 필수(카메라 API는 localhost 또는 HTTPS에서만 동작).

## 6. 한계 및 확장
- Passive PAD 점수는 클라이언트 산출 → 고위험 환경에서는 서버측 ONNX 안티스푸핑(MiniFASNet) 재추론 또는 적외선/깊이 카메라 권장.
- 다중 야자실, 학부모 알림(카카오 알림톡), PWA 오프라인 설치 확장 가능.
